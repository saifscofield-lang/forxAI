## 3. Shadow-signals pipeline — RESTORED 2026-04-22

**What happened:** Commit `524131e` (2026-04-16 18:44 UTC) added `data_group="STABLE"` kwarg to `ShadowSignal(...)` constructor, but the ORM model didn't declare that column (it was added to the SQLite table on 2026-04-14 via raw `ALTER TABLE`, never reflected in `storage/database.py`). Silent `TypeError` swallowed by surrounding try/except. **73 errors across 6 days. ~200 shadow rows lost (unrecoverable).**

**Resolution timeline:**
- 2026-04-22 (today) — root cause diagnosed, 1-line Column declaration added to `ShadowSignal`, engine restarted, writes verified (`total=238`, `stable=111`, `last_ts=2026-04-22 15:52:09`).
- 2026-04-22 — same-class latent-drift bugs in `Trade` and `TradeResult` models also closed (3 more Column declarations). All 6 ORM models now drift-clean vs live DB.

**Remaining concern for this meeting:** we have a **6-day hole in STABLE shadow data** (2026-04-16 18:05 to 2026-04-22 15:52 UTC). That gap cannot be backfilled — the signal context wasn't persisted elsewhere.

**Implication for Phase 7 / 8:**
- Phase 7 (Meta-Labeler Rebuild) trains on the full 1,144-signal dataset frozen at 2026-04-17 — **not** on shadow-period data. The shadow gap does **not** affect Phase 7 start.
- Phase 8 (v3.0 Paper Trading starting Jun 8) consumes forward-going shadow data for ongoing filter calibration. Those 6 days of lost data would have been part of the May-early-June warm-up. The meeting should decide whether to accept the hole or extend the warm-up window by 6 days (Jun 14 start instead of Jun 8).

**Honest framing for the meeting:**
