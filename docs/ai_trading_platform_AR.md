## 1. معمارية النظام العامة

### 1.1 المعمارية عالية المستوى

```
┌──────────────────────────────────────────────────────────────────────────┐
│                         مصادر البيانات الخارجية                          │
│  [الوسطاء/البورصات]  [موردو بيانات السوق]  [واجهات الأخبار]  [السلسلة]  │
└───────────────────────────────┬──────────────────────────────────────────┘
                                │
                    ┌───────────▼────────────┐
                    │   طبقة استيعاب البيانات │
                    │  (بث مباشر + دفعات)    │
                    └───────────┬────────────┘
                                │
              ┌─────────────────▼─────────────────┐
              │         طبقة منصة البيانات         │
              │  [التحقق] [التخزين] [الفهرسة]      │
              └─────────────────┬─────────────────┘
                                │
         ┌──────────────────────▼──────────────────────┐
         │           طبقة هندسة الميزات                 │
         │  [تقنية] [إحصائية] [أساسية]                  │
         │  [مشاعر] [بنية مجهرية] [كلية]               │
         └──────────────────────┬──────────────────────┘
                                │
    ┌───────────────────────────▼───────────────────────────┐
    │              طبقة الذكاء الاصطناعي / التعلم الآلي      │
    │  [تدريب النماذج] [سجل النماذج] [كشف النظام]            │
    │  [محرك التنبؤ] [موجّه المجموعات]                       │
    └───────────────────────────┬───────────────────────────┘
                                │
   ┌────────────────────────────▼────────────────────────────┐
   │              طبقة تنسيق الاستراتيجيات                    │
   │  [مكتبة الاستراتيجيات] [محرك الاختبار الخلفي] [مرتّب]   │
   │  [محرك القرار] [مجمّع الإشارات]                         │
   └────────────────────────────┬────────────────────────────┘
                                │
     ┌──────────────────────────▼──────────────────────────┐
     │               طبقة إدارة المخاطر                     │
     │  [محدد الحجم] [حارس التراجع] [مفتاح الإيقاف]         │
     │  [تعرض المحفظة] [محرك VaR/CVaR]                     │
     └──────────────────────────┬──────────────────────────┘
                                │
          ┌─────────────────────▼──────────────────────┐
          │               طبقة التنفيذ                   │
          │  [موجّه الأوامر] [OMS ذكي] [واجهات الوسطاء]  │
          │  [مراقب الانزلاق] [محلل التعبئة]             │
          └─────────────────────┬──────────────────────┘
                                │
       ┌────────────────────────▼────────────────────────┐
       │          طبقة المراقبة وقابلية الرصد              │
       │  [لوحات مراقبة فورية] [تنبيهات] [سجلات التدقيق]  │
       │  [كشف انجراف النموذج] [تحليلات الأداء]           │
       └────────────────────────────────────────────────┘
```

### 1.2 ملخص طبقات النظام

| الطبقة | المسؤولية |
|---|---|
| استيعاب البيانات | جمع بيانات السوق الخام والبديلة والأساسية |
| منصة البيانات | التحقق من البيانات وتطبيعها وتخزينها وفهرستها |
| هندسة الميزات | تحويل البيانات الخام إلى إشارات جاهزة للتعلم الآلي |
| الذكاء الاصطناعي/التعلم الآلي | تدريب النماذج وإصدارها وخدمتها وتوجيهها |
| تنسيق الاستراتيجيات | توليد الاستراتيجيات واختبارها وترتيبها وتفعيلها |
| إدارة المخاطر | تمرير جميع القرارات عبر قواعد المخاطر قبل التنفيذ |
| التنفيذ | توجيه الأوامر وإدارتها لدى الوسطاء/البورصات |
| المراقبة | رصد صحة النظام وأدائه وسلوك النماذج |

### 1.3 تدفق البيانات

```
بيانات التيك الخام
  ← استيعاب (Kafka/WebSocket)
    ← تحقق (مخطط، كشف القيم الشاذة)
      ← تخزين (TimescaleDB / Arctic / S3)
        ← مخزن الميزات (Feast / Redis)
          ← نماذج التعلم الآلي (التنبؤ بقوة الإشارة + الاتجاه)
            ← كشف النظام (تصنيف حالة السوق)
              ← موجّه الاستراتيجيات (اختيار الاستراتيجيات النشطة لكل نظام)
                ← مجمّع الإشارات (دمج الإشارات)
                  ← محرك القرار (توليد اقتراح الأمر)
                    ← بوابة المخاطر (موافقة/رفض/تغيير الحجم)
                      ← محرك التنفيذ (توجيه إلى الوسيط)
                        ← تغذية راجعة للتعبئة ← قاعدة بيانات الأداء ← حلقة إعادة التدريب
```

## 2. الوحدات الأساسية

### 2.1 استيعاب البيانات (`ingestion/`)

- **جامع التيك**: بث WebSocket للبيانات الفورية OHLCV، دفتر الأوامر L2، الصفقات
- **محمّل الدُّفعات**: بيانات نهاية اليوم، التقارير الأساسية، المؤشرات الكلية عبر REST APIs
- **البيانات البديلة**: موجزات الأخبار (خط أنابيب NLP)، المشاعر الاجتماعية (Twitter/Reddit)، المقاييس على السلسلة (crypto)، تقارير COT
- **سجل المخطط**: يطبّق عقود البيانات باستخدام مخططات Avro أو Protobuf
- **طابور الرسائل المرفوضة (DLQ)**: توجيه الرسائل الفاشلة لإعادة المعالجة

### 2.2 التحقق من البيانات (`validation/`)

- **التحقق من المخطط**: يضمن أنواع الحقول والنطاقات والأعمدة المطلوبة
- **كاشف الشذوذات**: اكتشاف Z-score / IQR لارتفاعات الأسعار وانعدام الحجم والتغذيات القديمة
- **فحوصات الاكتمال**: كشف الفجوات في السلاسل الزمنية
- **التسوية بين المصادر**: مقارنة نفس الأداة عبر مصادر متعددة
- **دفتر جودة البيانات**: يتتبع درجات الجودة لكل مصدر لكل رمز

### 2.3 هندسة الميزات (`features/`)

| فئة الميزة | أمثلة |
|---|---|
| تقنية | RSI، MACD، بولينجر باند، ATR، VWAP، OBV |
| إحصائية | المتوسط/الانحراف المتدحرج، الارتباط الذاتي، التكامل المشترك، مؤشر هيرست |
| البنية المجهرية | فارق العرض/الطلب، اختلال دفتر الأوامر، سمية تدفق التداول (VPIN) |
| النظام | نظام التقلب، قوة الاتجاه، نظام الارتباط |
| المشاعر | درجات NLP من الأخبار/وسائل التواصل، مؤشر الخوف/الجشع |
| أساسية | نسبة P/E، مفاجأة الأرباح، المؤشرات الكلية (CPI، الفائدة) |
| مشتقة | تقاطعات الميزات، مكونات PCA، تحليل المويجات |

- **مخزن الميزات**: Feast أو Hopsworks للوصول الفوري (زمن تأخير منخفض) + الوضع غير المتصل (التدريب الدفعي)
- **تعيين إصدارات الميزات**: تتبع تعريفات الميزات والتحويلات
- **سجل أهمية الميزات**: أهمية قائمة على SHAP تُتتبع لكل نموذج

### 2.4 خط أنابيب تدريب النموذج (`ml/training/`)

- **تتبع التجارب**: MLflow يتتبع جميع عمليات التشغيل والمعاملات الفائقة والمقاييس
- **التدريب الموزع**: Ray Train / Dask للتدريب المتوازي للنماذج
- **التحقق المتقاطع**: Purged K-Fold (يمنع تحيز النظر للمستقبل في السلاسل الزمنية)
- **تحسين المعاملات الفائقة**: Optuna / Ray Tune مع التحسين البايزي
- **قابلية الاستنساخ**: إدارة البذور، لقطات البيئة، تعيين إصدارات البيانات (DVC)

### 2.5 سجل النماذج (`ml/registry/`)

- **نماذج ذات إصدارات**: MLflow Model Registry بدورة حياة تدريجي → إنتاج
- **بيانات وصفية للنموذج**: تاريخ التدريب، إصدار مجموعة البيانات، مقاييس الأداء، قائمة الميزات
- **بطل/مُتحدٍّ**: إطار عمل اختبار A/B لمقارنة النماذج في الإنتاج
- **دعم التراجع**: العودة الفورية إلى نموذج البطل السابق

### 2.6 كشف نظام السوق (`regime/`)

- **نموذج ماركوف المخفي (HMM)**: اكتشاف حالات النظام الكامنة (اتجاه، ارتداد متوسط، متقلب، محدود النطاق)
- **التجميع**: K-Means / GMM على ميزات التقلب والاتجاه والارتباط
- **التصنيف القائم على القواعد**: مستويات VIX، عتبات ADX، أنظمة التقلب المحقق
- **درجة ثقة النظام**: توزيع الاحتمالية على الحالات، وليس مجرد تصنيف ثنائي
- **واجهة برمجة تطبيقات النظام**: جميع الاستراتيجيات تستعلم عن النظام الحالي قبل توليد الإشارات

### 2.7 توليد الاستراتيجيات (`strategies/`)

- توليد تلقائي عبر الخوارزميات الجينية أو توليد الفرضيات بمساعدة LLM
- تأليف يدوي من قِبَل المحللين الكميين باستخدام فئة `Strategy` الأساسية الموحدة
- كل استراتيجية عديمة الحالة — تُدار جميع الحالات بواسطة طبقة التنسيق

### 2.8 تقييم الاستراتيجيات (`backtest/`)

- **محاكٍ خلفي متجه**: Backtrader / NumPy مخصص للسرعة
- **محاكٍ خلفي مدفوع بالأحداث**: محاكاة واقعية مع الانزلاق والرسوم والتعبئات الجزئية
- **تحسين التقدم للأمام (Walk-Forward)**: منع التحسين المفرط للبيانات
- **محاكاة مونت كارلو**: اختبار الإجهاد في ظروف عشوائية
- **المقاييس**: شارب، سورتينو، كالمار، أقصى تراجع، عامل الربح، معدل الفوز، التوقع

### 2.9 محرك القرار (`engine/`)

- **مجمّع الإشارات**: مجموعة مرجحة من إشارات الاستراتيجيات النشطة
- **عتبة الثقة**: التصرف فقط على إشارات تتجاوز الحد الأدنى من الثقة
- **محلل التعارض**: معالجة الإشارات المتعارضة عبر الاستراتيجيات
- **مولّد اقتراح الأمر**: يحوّل الإشارة إلى اقتراح أمر منظم (رمز، اتجاه، طلب_الحجم)
- **فحص ما قبل المخاطرة**: فحوصات أولية قبل التحويل إلى طبقة المخاطر

- **مدير الارتباط**: منع التركّز الزائد في الأصول المترابطة
- **مخصص رأس المال**: توزيع ديناميكي عبر الاستراتيجيات باستخدام معيار كيلي أو تعادل التقلب
- **محرك إعادة التوازن**: تفعيل إعادة التوازن عند تجاوز عتبات الانجراف

## 3. مكونات الذكاء الاصطناعي والتعلم الآلي

### 3.1 مجموعة النماذج (Model Zoo)

#### نماذج التعلم العميق

| النموذج | حالة الاستخدام | متى يُستخدم |
|---|---|---|
| LSTM / GRU | تعلم أنماط الأسعار المتسلسلة | إشارات متوسطة التردد، التقاط الاتجاه |
| Temporal Fusion Transformer (TFT) | التنبؤ متعدد الأفق مع قابلية التفسير | التنبؤ متعدد الخطوات بالسعر/التقلب |
| Transformer (مخصص) | التبعية بعيدة المدى في السلاسل الزمنية المالية | نمذجة الارتباط عبر الأصول |
| CNN-1D | كشف الأنماط المحلية في تسلسلات OHLCV | التعرف على أنماط الرسم البياني قصيرة الأجل |
| Autoencoder | كشف الشذوذات، ترميز النظام | اكتشاف ظروف السوق غير العادية |

#### نماذج السلاسل الزمنية المتخصصة

| النموذج | حالة الاستخدام |
|---|---|
| N-BEATS | التنبؤ بالسلاسل الزمنية بالتعلم العميق البحت |
| Prophet | خط أساس الاتجاه الكلي/الأساسي |
| ARIMA / SARIMA | خط أساس المكون المستقر |
| عائلة GARCH | التنبؤ بالتقلب (التنبؤ بالتقلب المحقق) |

#### تعزيز التدرج (Gradient Boosting)

| النموذج | حالة الاستخدام |
|---|---|
| LightGBM | التصنيف/الانحدار الأساسي للميزات الجدولية |
| XGBoost | GBM بديل مع دعم نظيفة أوسع |
| CatBoost | يتعامل مع الميزات الفئوية (القطاع، البورصة، الرمز) |

**الاستخدام الأساسي**: التنبؤ باتجاه عائد الشريط التالي N، تصنيف النظام، ترتيب أهمية الميزات.

#### التعلم المعزز (Reinforcement Learning)

| الخوارزمية | حالة الاستخدام |
|---|---|
| PPO (تحسين السياسة القريبة) | تعلم سياسة التداول الشامل |
| SAC (فاعل-ناقد ناعم) | مساحات العمل المستمرة (تحديد حجم المركز) |
| DQN / DDQN | عميل تداول الإجراءات المنفصلة |
| RL متعدد الوكلاء | المنافسة بين الاستراتيجيات / توزيع المحفظة |

**يُستخدم التعلم المعزز في**: تعلم استراتيجيات التنفيذ، سياسات تحديد حجم المركز، وسياسات توزيع المحفظة — وليس التنبؤ الخام بالسعر.

#### الأنظمة الجماعية (Ensemble Systems)

```
تنبؤات النماذج الفردية
        │
        ▼
┌──────────────────────────────┐
│       موجّه المجموعة          │
│  (مشروط بالنظام)             │
│                              │
│  سوق اتجاهي     → LSTM       │
│  ارتداد متوسط   → GBM        │
│  تقلب عالٍ      → GARCH      │
│  إشارة ضعيفة    → مزج        │
└──────────────┬───────────────┘
               │
               ▼
    تعلم ميتا (Stacking)
    (LightGBM على مخرجات النماذج)
               │
               ▼
    نتيجة الإشارة النهائية [-1, +1]
```

### 3.2 كيف تصبح التنبؤات قرارات تداول

```
1. متجه الميزات (t) ← مخزن الميزات
2. متجه الميزات ← النماذج النشطة (استدلال متوازٍ)
3. مخرجات النموذج: [احتمال_الاتجاه، تنبؤ_الحجم، الثقة]
4. سياق النظام ← موجّه المجموعة يختار/يرجّح النماذج
5. تعلم الميتا يُنتج final_signal ∈ [-1.0, +1.0]
6. الإشارة > عتبة_الشراء  ← اقتراح شراء
   الإشارة < عتبة_البيع   ← اقتراح بيع
   غير ذلك                ← لا إجراء
7. الاقتراح ← بوابة المخاطر ← التنفيذ
```

## 4. إطار عمل الاستراتيجيات

### 4.1 الفئة الأساسية للاستراتيجية

```python
class Strategy(ABC):
    id: str
    version: str
    regime_filter: list[RegimeState]    # فلتر النظام
    instruments: list[str]              # الأدوات المالية
    timeframes: list[Timeframe]         # الأطر الزمنية

    @abstractmethod
    def generate_signal(self, features: FeatureVector) -> Signal:
        ...  # توليد الإشارة

    @abstractmethod
    def get_parameters(self) -> dict:
        ...  # الحصول على المعاملات
```

### 4.2 دورة حياة الاستراتيجية

```
فكرة ← توليد ← اختبار خلفي ← تداول ورقي ← ظل ← مباشر ← أرشفة
          │           │              │          │      │
    (تلقائي/يدوي)  (تقدم للأمام)  (رأس مال محاكى) (صغير) (كامل)
```

### 4.3 أنواع الاستراتيجيات

| الفئة | أمثلة |
|---|---|
| تتبع الاتجاه | تقاطع المتوسطات المتحركة، الاختراق، الزخم |
| الارتداد للمتوسط | قيم RSI المتطرفة، ضغط بولينجر، أزواج التكامل المشترك |
| المراجحة الإحصائية | تداول الأزواج، مراجحة ETF، تداول الفارق |
| مدفوع بالتعلم الآلي | إشارة بحتة من مخرج النموذج (بدون قواعد) |
| هجين | دخول قائم على القواعد + تحديد الحجم/الخروج بالتعلم الآلي |
| كلي | مدفوع بالأحداث حول FOMC وCPI والأرباح |

### 4.4 التوليد التلقائي للاستراتيجيات

- **البرمجة الجينية**: تطور قواعد الاستراتيجية باستخدام مكتبة DEAP
- **البحث في فضاء المعاملات**: البحث الشبكي/البايزي على فضاء معاملات الاستراتيجية
- **توليد الفرضيات بواسطة LLM**: GPT-4 يولّد فرضيات الاستراتيجية بشكل منظم، يُختبر تلقائياً خلفياً
- **محرك الطفرة**: تحوير الاستراتيجيات المربحة الموجودة لاكتشاف متغيرات جديدة

### 4.5 ترتيب وتفعيل الاستراتيجيات

```
درجة الاختبار الخلفي = w1×شارب + w2×كالمار + w3×(1/أقصى_تراجع) + w4×الاستقرار

معايير التفعيل:
  - شارب > 1.5 (اختبار خلفي)
  - أقصى تراجع < 15%
  - 200 صفقة كحد أدنى في الاختبار الخلفي
  - اجتياز مرحلة التداول الورقي (≥30 يوماً)
  - مناسبة للنظام الحالي

الاستراتيجيات النشطة لكل نظام:
  - أعلى N استراتيجيات لكل حالة نظام (الافتراضي N=5)
  - رأس المال المخصص يتناسب مع درجة الترتيب
  - إلغاء تفعيل تلقائي إذا انخفض شارب المباشر إلى ما دون 0.5
```

## 5. طبقة إدارة المخاطر

### 5.1 تحديد حجم المركز

```
كسر كيلي:  f = (bp - q) / b
  حيث: b = الاحتمالات، p = احتمال الفوز، q = 1-p

كيلي الجزئي: الحجم = f × 0.25 × قيمة_المحفظة  (25% كيلي للأمان)

المعدَّل حسب التقلب:
  الحجم = (المخاطرة_لكل_صفقة / ATR_20) × قيمة_النقطة

الحجم الأقصى للمركز = min(حجم_كيلي، الحجم_المعدَّل_للتقلب، حد_المركز_الأحادي_الأقصى)
```

### 5.2 التحكم في التراجع

| المستوى | المُشغِّل | الإجراء |
|---|---|---|
| تحذير | تراجع > 5% | تخفيض أحجام جميع المراكز بنسبة 25% |
| تنبيه | تراجع > 10% | تخفيض الأحجام بنسبة 50%، تنبيه فريق المخاطر |
| حرج | تراجع > 15% | إيقاف الدخولات الجديدة، تسطيح المراكز الموجودة |
| طارئ | تراجع > 20% | تصفية كاملة للمحفظة، إيقاف النظام |

### 5.3 المخاطر القائمة على التقلب

- **القيمة المعرضة للخطر (VaR)**: حد VaR يومي بنسبة 99% لكل أداة وللمحفظة
- **القيمة المعرضة للخطر المشروطة (CVaR)**: قيد مخاطر الذيل ما وراء VaR
- **تحجيم التقلب**: أحجام المراكز مُعكوسة نسبياً مع تقلب 20 يوم محقق
- **حدود الارتباط**: أقصى ارتباط زوجي 0.7 بين المراكز النشطة

### 5.4 مفتاح الإيقاف الطارئ (Kill Switch)

```python
class KillSwitch:
    المُشغِّلات:
      - خسائر_متتالية > 5
      - خسارة_ساعية > أقصى_خسارة_ساعية
      - شذوذ_حجم_المركز (>3σ عن الطبيعي)
      - معدل_فشل_التنفيذ > 10%
      - زمن_تأخير_تغذية_البيانات > 500ms
      - متوسط_ثقة_النموذج < 0.4
      - ارتفاع_مفاجئ_في_التعرض

    الإجراءات:
      - إيقاف_ناعم: لا دخولات جديدة، إدارة الموجود
      - إيقاف_كامل: تسطيح جميع المراكز فوراً
      - إيقاف_النظام: إيقاف جميع التداولات + تنبيه البشر
```

### 5.5 حدود تعرض المحفظة

| القيد | الحد |
|---|---|
| الحد الأقصى لأداة واحدة | 10% من صافي الأصول |
| الحد الأقصى لقطاع/عملة | 25% من صافي الأصول |
| الحد الأقصى للمجموعة المترابطة | 30% من صافي الأصول |
| أقصى رافعة إجمالية | 3 أضعاف صافي الأصول |
| أقصى رافعة صافية | 1.5 ضعف صافي الأصول |
| أقصى تعرض ليلي | 50% من صافي الأصول |

## 6. نظام التنفيذ

### 6.1 نظام إدارة الأوامر (OMS)

```
محرك القرار
    │ اقتراح الأمر
    ▼
فحص المخاطر قبل التداول (طبقة المخاطر)
    │ أمر معتمد
    ▼
موجّه الأوامر
    ├─← الوسيط الأساسي (Interactive Brokers / Alpaca / Binance)
    ├─← الوسيط الثانوي (احتياطي)
    └─← التداول الورقي (وضع الظل)
    │
    ▼
مراقب الأوامر (تتبع التعبئة، التعبئات الجزئية، انتهاء المهلة)
    │
    ▼
معالج التعبئة ← متتبع المراكز ← محرك الربح والخسارة
```

### 6.2 اعتبارات زمن الاستجابة

| المكون | زمن الاستجابة المستهدف |
|---|---|
| توليد الإشارة (استدلال التعلم الآلي) | < 50ms |
| فحص المخاطر | < 5ms |
| توجيه الأوامر (REST) | < 100ms |
| توجيه الأوامر (FIX/WebSocket) | < 10ms |
| إجمالي من الإشارة إلى الأمر | < 200ms |

- يُوصى بالتمركز المشترك لاستراتيجيات HFT
- I/O غير متزامن في جميع أنحاء مكدس التنفيذ (asyncio / aiohttp)
- تجميع الاتصالات لواجهات برمجة تطبيقات الوسيط

### 6.3 أنواع الأوامر

| نوع الأمر | متى يُستخدم |
|---|---|
| سوق | الأدوات عالية السيولة، الدخولات العاجلة |
| محدد | الدخولات القياسية، التحكم في سعر التعبئة |
| وقف-محدد | الخروجات الوقائية |
| TWAP/VWAP | الأوامر الكبيرة لتقليل تأثير السوق |
| جبل الجليد | الأوامر الكبيرة — إخفاء الحجم الكامل |
| حامل (Bracket) | دخول + وقف خسارة + جني أرباح في أمر واحد |

### 6.4 التحكم في الانزلاق

- **تقدير الانزلاق قبل التداول**: بناءً على الفارق التاريخي + نموذج تأثير السوق
- **ميزانية الانزلاق**: الحد الأقصى للانزلاق المسموح به لكل أمر؛ الإلغاء عند تجاوزه
- **تحجيم تكيّفي**: تقليل الحجم في فترات انخفاض السيولة
- **نموذج تكلفة المعاملة**: نموذج معايَر لكل أداة لكل بورصة

### 6.5 تكامل الوسيط/البورصة

```

├── interactive_brokers.py   (TWS API / IB Gateway)
├── alpaca.py                (REST + WebSocket)
```

## 7. حلقة التعلم والتحسين المستمر

### 7.1 معمارية التغذية الراجعة المستمرة

```
صفقات مباشرة
    │
    ▼
قاعدة بيانات نتائج الصفقات
    │
    ├─← مخزن الميزات ←─ (تسمية: العائد الفعلي، فوز/خسارة)
    │
    ▼
خط أنابيب إعادة تدريب النموذج
    │
    ├─← التعلم الإلكتروني (تحديث تدريجي للتكيف السريع)
    └─← إعادة التدريب غير المتصلة (إعادة تدريب كاملة على نافذة متدحرجة)
    │
    ▼
تقييم النموذج (اختبار خلفي على بيانات OOS حديثة)
    │
    ├─ أفضل؟ ← ترقية إلى مُتحدٍّ ← اختبار A/B ← ترقية إلى بطل
    └─ أسوأ؟  ← أرشفة، تنبيه الفريق
```

### 7.2 جدول إعادة التدريب

| نوع النموذج | تكرار إعادة التدريب |
|---|---|
| إشارات التعلم الآلي قصيرة الأجل | يومياً (نافذة متدحرجة 6 أشهر) |
| مصنّف النظام | أسبوعياً |
| نماذج التعلم العميق | شهرياً (تكلفة حسابية عالية) |
| نماذج المخاطر (GARCH) | يومياً |
| وكلاء التعلم المعزز | أسبوعياً (تحديثات بيئية مستمرة) |

### 7.3 تحليل أداء الاستراتيجية

- **مراقب شارب المتدحرج**: شارب متدحرج 30 يوماً لكل استراتيجية مباشرة
- **تفصيل الأداء حسب النظام**: تتبع أداء الاستراتيجية لكل نظام مكتشف
- **كاشف التدهور**: اختبار إحصائي (CUSUM) للكشف عن تدهور الأداء
- **الأرشفة التلقائية**: الاستراتيجيات ذات شارب متدحرج < 0.3 لمدة 30+ يوماً تُلغى

### 7.4 الأنظمة التكيفية

- **التعديل الديناميكي للمعاملات**: معاملات الاستراتيجية تُضبط تلقائياً بناءً على ظروف السوق الأخيرة
- **نماذج مشروطة بالنظام**: النماذج تُعاد تدريبها بشكل منفصل لكل حالة نظام
- **كشف انجراف المفهوم**: خوارزميات DDM / ADWIN تكتشف متى تتحول ديناميكيات السوق
- **إعادة توزيع رأس المال**: إعادة توازن أسبوعية لتوزيع رأس المال عبر الاستراتيجيات

## 8. المراقبة وقابلية الرصد

### 8.1 مكدس المراقبة في الوقت الفعلي

```
المقاييس ← Prometheus ← لوحات Grafana
السجلات  ← Fluentd   ← Elasticsearch ← Kibana
التتبع   ← OpenTelemetry ← Jaeger
التنبيهات ← Alertmanager ← PagerDuty / Slack / بريد إلكتروني
```

### 8.2 لوحات المراقبة

| اللوحة | المقاييس الرئيسية |
|---|---|
| صحة النظام | CPU، الذاكرة، زمن الاستجابة، معدلات الأخطاء، عمق الطوابير |
| التداول | الربح والخسارة (يومي، MTD، YTD)، المراكز، التعرض |
| النموذج | دقة التنبؤ، توزيع الثقة، درجات الانجراف |
| المخاطر | VaR، CVaR، التراجع، حالة مفتاح الإيقاف |
| الاستراتيجية | شارب لكل استراتيجية، معدل الفوز، عدد الصفقات، التخصيص |
| التنفيذ | معدلات التعبئة، الانزلاق، معدلات الرفض، زمن استجابة الوسيط |

### 8.3 التنبيهات

| المُشغِّل | الخطورة | الإجراء |
|---|---|---|
| فجوة تغذية البيانات > 30 ثانية | تحذير | إعادة اتصال تلقائي + إشعار |
| تجاوز حد المركز | حرج | حجب الأمر + إشعار |
| تراجع > 5% | تحذير | تخفيض الحجم + إشعار |
| انخفاض دقة النموذج > 10% | تحذير | وضع علامة للمراجعة |
| تفعيل مفتاح الإيقاف | حرج | استدعاء المهندس المناوب |
| معدل خطأ التنفيذ > 5% | عالٍ | التبديل إلى الوسيط الاحتياطي |

### 8.4 كشف انجراف النموذج

- **انجراف البيانات**: تباعد KL / مؤشر استقرار السكان (PSI) على توزيعات الميزات
- **انجراف المفهوم**: مراقبة توزيعات التنبؤ مقابل النتائج الفعلية
- **انجراف الأداء**: اختبار CUSUM على مقاييس الدقة المتدحرجة
- **الاستجابة التلقائية**: تحديد ← تقليل تحديد حجم المركز ← تفعيل إعادة التدريب إذا تأكد الانجراف

### 8.5 مسار التدقيق

- كل أمر وقرار مخاطر وتنبؤ نموذج وتغيير معاملات يُسجَّل بشكل غير قابل للتغيير
- معمارية مصدر الأحداث: يمكن إعادة بناء الحالة الكاملة للنظام من سجل الأحداث
- سجلات جاهزة للامتثال مع طوابع زمنية ومعرّفات المستخدم/النظام
